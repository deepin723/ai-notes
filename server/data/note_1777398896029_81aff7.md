## 统一技术栈

三款产品（ai-chat / ai-image / Vki）采用完全一致的技术栈，降低维护成本，提升开发效率。

## 前端统一选型

**Vue 3 + TypeScript + Vite**

- Vue 3 Composition API：逻辑复用能力强，响应式设计简洁
- TypeScript：类型安全，IDE 提示完整，重构可靠
- Vite：极速 HMR，构建快，原生 ESM
- 无 UI 框架：全部手写样式，产品风格高度定制化

## 后端统一选型

**Node.js + Express**

- 语言统一：前后端同为 JS/TS，降低上下文切换成本
- Express：轻量无侵入，适合 API 代理场景
- ESM 模式（type: module）：统一模块规范
- 无 ORM：ai-chat/ai-image 无数据库；Vki 使用文件系统

## 部署架构

```
用户浏览器
    ↓ HTTPS
Vercel CDN（全球边缘）
    ↓ 静态资源
Vue 3 SPA
    ↓ API 请求（带 x-api-key / x-base-url header）
Railway（Docker 容器）
    ↓ 转发
OpenAI 兼容 API（用户自己的 endpoint）
```

## 为什么选择 Railway + Docker

### 问题背景
后端服务需要长连接（SSE 流式）、自定义 Node 版本、持久进程，Serverless（如 Vercel Functions）无法满足：
- SSE 流式接口需要长连接，Serverless 60s 超时
- 图像生成耗时 2-5 分钟，必须常驻进程

### Docker 的作用
Railway 以 Docker 容器运行服务：
1. **环境一致性**：本地 node --watch 与生产 node index.js 运行在相同镜像中
2. **依赖隔离**：每个项目独立容器，依赖不污染宿主机
3. **自动构建**：push to GitHub → Railway 自动构建 Docker 镜像 → 滚动部署
4. **进程管理**：容器崩溃自动重启，无需 PM2
5. **扩容简单**：需要时水平扩展多个容器实例

### Vercel 的作用
- 静态文件 + CDN 分发，全球访问速度快
- 自动 HTTPS
- GitHub push → 自动重新构建前端
- vercel.json 中配置 rewrites，将 /api/* 请求代理到 Railway

## API Key 安全设计

- 用户 Key 存储在浏览器 localStorage，不上传服务器
- 每次请求通过 HTTP Header（x-api-key、x-base-url）传递
- 后端只做代理转发，不持久化 Key
- 服务端无用户数据库，天然零数据风险

## 开发工作流

1. 本地开发：npm run dev（concurrently 同时启动前后端）
2. 前端：Vite dev server，HMR 热更新
3. 后端：node --watch，文件变更自动重启
4. 提交：git push → GitHub → 触发 Railway/Vercel 自动部署
5. 生产：Railway 后端 + Vercel 前端，约 2-3 分钟部署完成
