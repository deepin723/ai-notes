## 项目定位

ai-image（Deepin Image）是一个**AI 图像生成平台**，核心特性是让图像生成不阻塞用户界面——用户提交任务后可以继续操作，任务在后台排队处理，完成后自动显示结果。

---

## 技术选型总览

| 层级 | 技术 | 解决的问题 |
|------|------|----------|
| 前端状态 | Vue 3 ref/computed | tasks[] 响应式数组驱动 UI |
| 图像生成 | gpt-image-2 via Responses API | 高质量图像，支持参考图 |
| 流式解析 | ReadableStream + TextDecoder | 服务端 SSE 提前提取图像 |
| 提示词增强 | LLM /chat/completions | 中文简描→专业英文 prompt |
| 参考图上传 | FileReader API + base64 | 实现图生图能力 |
| 设计语言 | 棕金色系 CSS 变量 | 艺廊风格，区别于 ai-chat |

## 核心 1：后台任务队列系统

### Task 数据模型

```typescript
interface Task {
  id:                   string    // 时间戳 ID（Date.now()）
  prompt:               string    // 最终 prompt（含风格标签）
  size:                 string    // 图像尺寸，如 '1024x1024'
  referenceImageBase64?: string   // 参考图 base64（图生图）
  referenceImageMime?:  string    // 参考图 MIME 类型
  status: 'queued' | 'generating' | 'done' | 'error'  // 状态机
  progress:             number    // 0-100，用于进度条
  msgIndex:             number    // 轮换提示语索引
  imageUrl?:            string    // 生成结果 data URL
  error?:               string    // 失败原因
  ts:                   number    // 时间戳
}

const tasks = ref<Task[]>([])  // 响应式数组，Vue 自动追踪变化
```

### 状态机流转

```
                   processNext()
                       ↓
[queued] ──────────→ [generating]
                       ↓ API 成功
                    [done]
                       ↓ 或 API 失败
                    [error]
```

### processNext() 核心逻辑

```typescript
let isProcessing = false  // 全局锁，防止并发处理

const processNext = async () => {
  if (isProcessing) return  // 已有任务在处理，退出
  const task = tasks.value.find(t => t.status === 'queued')
  if (!task) return          // 队列为空，退出

  isProcessing = true
  task.status = 'generating'
  task.progress = 0

  // ① 进度条动画（乐观动画，0→88%，25秒内线性增长）
  const pt = setInterval(() => {
    if (task.progress < 88) {
      const inc = Math.max(0.4, (88 - task.progress) / 25)
      task.progress = Math.min(88, task.progress + inc)
    }
  }, 1000)

  // ② 提示语轮换（每4秒切换一条鼓励文字）
  const mt = setInterval(() => {
    task.msgIndex = (task.msgIndex + 1) % LOADING_MSGS.length
  }, 4000)

  try {
    // ③ 调用后端 API
    const res = await fetch('/api/generate-image', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json',
                 'x-api-key': apiKey, 'x-base-url': baseUrl },
      body: JSON.stringify({
        prompt: task.prompt,
        size:   task.size,
        referenceImageBase64: task.referenceImageBase64,
        referenceImageMime:   task.referenceImageMime,
      }),
    })
    const data = await res.json()

    if (data.imageBase64) {
      // ④ 成功：进度跳到 100%，存储图像 URL
      task.status   = 'done'
      task.progress = 100
      task.imageUrl = 'data:image/png;base64,' + data.imageBase64

      // 加入历史记录
      history.value.unshift({ id: task.id, prompt: task.prompt,
                               imageUrl: task.imageUrl, ts: task.ts })
    } else {
      task.status = 'error'
      task.error  = data.error || '未知错误'
    }
  } catch (e) {
    task.status = 'error'
    task.error  = '网络请求失败'
  } finally {
    clearInterval(pt)  // 清理进度计时器
    clearInterval(mt)  // 清理消息计时器
    isProcessing = false
    processNext()      // ⑤ 处理下一个队列任务（递归）
  }
}
```

**设计亮点：**
- `isProcessing` 布尔锁保证串行处理，不并发（避免 API 限流）
- 进度条「乐观动画」：先到 88%，完成时跳 100%，给用户「快完成了」的感知
- `processNext()` 尾递归：每个任务完成自动触发下一个，无限队列

## 核心 2：后端 SSE 解析提前取图

### 为什么需要提前退出

gpt-image-2 的 `/responses` 接口返回一个 SSE 流，流里包含文字解释 + 图像数据。完整等待流结束可能需要额外几十秒。当我们拿到图像 base64 后，后续数据对我们没有价值，应该立刻返回。

### server/index.js 流式解析实现

```javascript
app.post('/api/generate-image', async (req, res) => {
  const { prompt, referenceImageBase64, referenceImageMime, size } = req.body
  const apiKey = req.headers['x-api-key']
  const baseUrl = req.headers['x-base-url'] || 'https://bobdong.cn/v1'

  // 构建请求内容（支持纯文字 或 文字+参考图）
  const inputContent = referenceImageBase64
    ? [
        { type: 'input_image',
          image_url: 'data:' + referenceImageMime + ';base64,' + referenceImageBase64 },
        { type: 'input_text', text: prompt }
      ]
    : prompt

  // 调用 Responses API（非标准 OpenAI 端点，支持 tools）
  const response = await fetch(baseUrl + '/responses', {
    method: 'POST',
    headers: { 'Authorization': 'Bearer ' + apiKey, 'Content-Type': 'application/json' },
    body: JSON.stringify({
      model: 'gpt-image-2',
      input: [{ role: 'user', content: inputContent }],
      tools: [{ type: 'image_generation', size: size || '1024x1024' }],
      stream: true,   // 开启 SSE 流
    }),
    signal: AbortSignal.timeout(600_000),  // 10分钟超时（图像生成慢）
  })

  // 逐行解析 SSE 流
  const reader  = response.body.getReader()
  const decoder = new TextDecoder()
  let buffer = ''
  let imageB64 = null

  outer: while (true) {
    const { done, value } = await reader.read()
    if (done) break

    buffer += decoder.decode(value, { stream: true })
    const lines = buffer.split('\n')
    buffer = lines.pop() ?? ''  // 最后一行可能不完整，留到下次

    for (const line of lines) {
      const trimmed = line.trim()
      if (!trimmed.startsWith('data:')) continue
      const dataStr = trimmed.slice(5).trim()
      if (dataStr === '[DONE]') break outer

      try {
        const data = JSON.parse(dataStr)
        // 查找「图像生成完成」事件
        if (data.type === 'response.output_item.done') {
          const item = data.item || {}
          if (item.type === 'image_generation_call' && item.result) {
            imageB64 = item.result  // ← 拿到 base64
            break outer             // ← 立刻退出，不等流结束
          }
        }
      } catch { /* 忽略 JSON 解析错误 */ }
    }
  }

  reader.cancel().catch(() => {})  // 取消未读完的流，释放连接

  if (imageB64) {
    res.json({ imageBase64: imageB64 })
  } else {
    res.status(500).json({ error: '未获取到图像数据' })
  }
})
```

**关键技术细节：**

| 技术点 | 说明 |
|--------|------|
| `buffer` 拼接 | 网络数据包不一定按行到达，需要拼接后再分行 |
| `lines.pop()` | 最后一行可能不完整，下次再处理 |
| `break outer` | 带标签 break 跳出外层 while，立刻退出 |
| `reader.cancel()` | 主动断开连接，不浪费带宽 |
| `AbortSignal.timeout(600_000)` | 10分钟超时，比 Vercel 60s 限制高很多 |

## 核心 3：提示词增强引擎

### 用户痛点

普通用户往往只会写「一只猫」「美丽的风景」这类简短描述，但 AI 图像模型对英文、细节丰富的 prompt 效果更好。

### server/index.js enhance-prompt 接口

```javascript
app.post('/api/enhance-prompt', async (req, res) => {
  const { prompt } = req.body

  const response = await fetch(baseUrl + '/chat/completions', {
    method: 'POST',
    headers: { 'Authorization': 'Bearer ' + apiKey, 'Content-Type': 'application/json' },
    body: JSON.stringify({
      model: 'gpt-4.1',
      messages: [
        {
          role: 'system',
          content: 'You are an expert at writing AI image generation prompts. \
            The user will provide a brief description in Chinese. \
            Expand it into a detailed, professional English prompt. \
            Include composition, lighting, style, mood, and color tone. \
            Output only the prompt text, no explanations, under 200 words.'
        },
        { role: 'user', content: prompt }
      ],
      max_tokens: 300,
    }),
  })

  const data = await response.json()
  const enhanced = data.choices[0].message.content.trim()
  res.json({ enhanced })
})
```

**增强效果示例：**

```
用户输入（中文）：  "一位戴草帽的女孩"

LLM 输出（英文）：  "A young girl wearing a rustic straw hat, standing in
                    a golden wheat field at sunset, warm golden hour
                    lighting casting long shadows, photorealistic
                    photography style, DSLR f/2.8 bokeh background,
                    peaceful pastoral atmosphere, film grain texture,
                    earth tones with amber and wheat gold color palette"
```

这段扩展后的 prompt 包含：构图（wheat field）、光线（golden hour）、风格（photorealistic）、技术参数（f/2.8 bokeh）、氛围（peaceful pastoral）、色调（amber and wheat gold）。

### 前端触发

```typescript
const isEnhancing = ref(false)

const enhancePrompt = async () => {
  if (!prompt.value.trim()) return
  isEnhancing.value = true  // 显示「优化中...」状态
  try {
    const res = await fetch('/api/enhance-prompt', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json',
                 'x-api-key': props.apiKey, 'x-base-url': props.baseUrl },
      body: JSON.stringify({ prompt: prompt.value }),
    })
    const data = await res.json()
    if (data.enhanced) {
      prompt.value = data.enhanced  // 直接替换输入框内容
    }
  } finally {
    isEnhancing.value = false
  }
}
```

## 核心 4：参考图上传（图生图）

```typescript
const refImageBase64  = ref('')  // base64 纯数据
const refImageMime    = ref('')  // 'image/jpeg' 等
const refImagePreview = ref('')  // data URL，用于预览 <img>

const onFileChange = (e: Event) => {
  const file = (e.target as HTMLInputElement).files?.[0]
  if (!file) return

  const reader = new FileReader()
  reader.onload = (ev) => {
    const result = ev.target?.result as string  // 'data:image/jpeg;base64,/9j/4AAQ...'
    refImagePreview.value = result
    refImageBase64.value  = result.split(',')[1]          // 只要逗号后面的 base64
    refImageMime.value    = result.match(/data:([^;]+);/)?.[1] || 'image/jpeg'
  }
  reader.readAsDataURL(file)  // FileReader 转 base64
}
```

**FileReader 工作原理：**
- `readAsDataURL()` 把文件读成 `data:image/jpeg;base64,...` 格式
- 我们用正则 `/data:([^;]+);/` 提取 MIME 类型
- 用 `split(',')[1]` 提取纯 base64 数据
- 这份 base64 随任务参数传给后端，后端重组成 multimodal input

## 核心 5：风格标签系统

```typescript
const STYLES = ['电影感', '写实摄影', '水彩插画', '赛博朋克',
                '胶片质感', '动漫风格', '油画质感', '极简主义']

const STYLE_EN: Record<string, string> = {
  '电影感':   'cinematic lighting, film look',
  '写实摄影': 'photorealistic, DSLR photography',
  '水彩插画': 'watercolor illustration style',
  '赛博朋克': 'cyberpunk aesthetic, neon lights',
  '胶片质感': 'film grain, analog photography, vintage',
  '动漫风格': 'anime style illustration',
  '油画质感': 'oil painting texture, painterly',
  '极简主义': 'minimalist design, clean composition',

const activeStyles = ref<string[]>([])  // 已选风格列表

// 构建最终 prompt
const buildPrompt = () => {
  const base = prompt.value.trim()

  return base + ', ' + activeStyles.value.map(s => STYLE_EN[s]).join(', ')
}
```

## 核心 6：计算属性驱动 UI 状态

```typescript
// 正在生成的任务（只会有0或1个）
const generatingTask = computed(() =>
  tasks.value.find(t => t.status === 'generating')
)

// 排队中的任务数量
const queuedCount = computed(() =>
  tasks.value.filter(t => t.status === 'queued').length
)

// 浮动面板显示文字（自动跟随状态变化）
const panelStatusText = computed(() => {
  if (generatingTask.value) {
    return queuedCount.value > 0
      ? '生成中 · 还有 ' + queuedCount.value + ' 个排队'
      : '生成中...'
  }
  const done = tasks.value.filter(t => t.status === 'done').length
  const err  = tasks.value.filter(t => t.status === 'error').length
  if (err > 0 && done === 0) return err + ' 个任务失败'
  if (err > 0) return done + ' 个完成 · ' + err + ' 个失败'
  return done + ' 个任务已完成'
})
```

`computed` 是 Vue 3 的响应式派生值，依赖的 `tasks` 变化时自动重计算，UI 自动更新，无需手动维护状态同步。

## 完整数据流图

```
用户操作
  [输入 prompt] + [选择风格] + [选尺寸] + [可选上传参考图]
                       ↓
           buildPrompt() → 合并风格标签
                       ↓
            点击「生成图片」
                       ↓
      创建 Task 对象 → push 到 tasks[]
                       ↓
           processNext() 被调用
                       ↓
      找到第一个 queued 任务 → status = 'generating'
      ┌─────────────────────────────────────────┐
      │ 同时启动：                               │
      │   进度动画：0→88%（1秒1次，持续25秒）    │
      │   消息轮换：每4秒切换提示语              │
      └─────────────────────────────────────────┘
                       ↓
      POST /api/generate-image
      Headers: x-api-key, x-base-url
      Body: { prompt, size, referenceImageBase64? }
                       ↓
      后端调用 ${baseUrl}/responses（SSE 流）
      逐行解析 data: {...} 事件
      找到 type='image_generation_call' → 提取 item.result
      break outer（提前退出，不等流结束）
      reader.cancel() 释放连接
                       ↓
      返回 { imageBase64: '...' }
                       ↓
      task.status = 'done'
      task.progress = 100
      task.imageUrl = 'data:image/png;base64,...'
      加入 history[]
      clearInterval() 清理计时器
      processNext() 处理下一个
```

## Vercel 部署配置

```json
// client/vercel.json
{
  "rewrites": [
    { "source": "/api/:path*",
      "destination": "https://your-railway-app.up.railway.app/api/:path*" }
  ]
}
```

Vercel 的 rewrites 把 `/api/*` 请求代理转发到 Railway 后端，前端代码无需改变。  
这与开发时 Vite 代理的作用相同，只是换成了 CDN 层的规则。
