子弹图片、刀光图片和音效文件不会自动产生打击感。它们必须在正确的位置、正确的时刻，与真正的命中结算一起出现。下面沿“一次按住射击产生的一发子弹”追踪整条链路。

## 一、弹体对象比弹体图片更重要

教学数据结构：

```js
const bullet = {
  x: muzzle.x, y: muzzle.y,
  vx: Math.cos(angle) * 1200,
  vy: Math.sin(angle) * 1200,
  damage: 34,
  pierce: 1,
  age: 0,
  alive: true,
  hitSet: new Set(),
  points: []
};
```

图片只是这个对象的表现。位置、速度、穿透、寿命和已命中目标决定行为。想把子弹从圆点改成细长闪线，不应顺便改掉命中范围或伤害次数；视觉与规则需要能独立调节。

每次更新先保留旧位置，再计算新位置。必须在旧点到新点之间检查碰撞，而不是只检查新点。

## 二、为什么高速子弹会穿过怪物却没伤害

假设子弹一秒走 1200 像素，某一帧耗时 50ms，它就前进 60 像素。怪物半径只有 16 像素时，子弹可能从怪物左边直接跳到右边，两端都不在怪物内部。

当前小焰 `combat.mjs` 的 `segmentHit()` 求线段与圆的首次交点。可以把运动写成 `P(t)=A+t(B-A)`，其中 t 在 0 到 1 之间；代入到圆心距离等于半径的方程，得到一元二次方程。

简化实现如下，与项目同一思路：

```js
function segmentHit(ax, ay, bx, by, cx, cy, r) {
  const dx = bx - ax, dy = by - ay;
  const ox = ax - cx, oy = ay - cy;
  const a = dx * dx + dy * dy;
  const c = ox * ox + oy * oy - r * r;
  if (c <= 0) return 0; // 起点已在圆内
  if (a < 1e-8) return null;
  const b = 2 * (ox * dx + oy * dy);
  const disc = b * b - 4 * a * c;
  if (disc < 0) return null;
  const t = (-b - Math.sqrt(disc)) / (2 * a);
  return t >= 0 && t <= 1 ? t : null;
}
```

同时碰到多个敌人时，按交点 t 从小到大处理，再扣穿透次数。否则数组里排在后方的怪可能先被命中。圆是游戏判定形状，不需要与图片轮廓逐像素一致；可额外把弹体半径加到敌人半径上。

## 三、刀光不能每帧都扣血

近战通常检测扇形：距离在范围内，目标与朝向夹角在半角内。因为攻击有效期跨多帧，同一个敌人会连续通过检测，所以每次攻击需要自己的 `hitSet`。

```js
if (inAttackArea(enemy) && !action.hitSet.has(enemy.id)) {
  action.hitSet.add(enemy.id);
  applyDamage(enemy, action.damage);
}
```

多段技能可给每一段独立命中集合，或明确使用“段编号 + 目标编号”。同样，伤害总线有 ticket 并不自动解决所有重复命中：如果每次循环都创建新 ticket，总线会认为是不同伤害。必须先在攻击层保证每段只触发一次。

现在正式关卡的 `GrowthRun.damage()` 会调用共享 `CombatRuntime.damageEnemy()`，再通过击杀事件掉落经验。视觉层不应自己偷偷再减一次 hp。

## 四、动画接触帧和伤害事件怎样同步

如果攻击接触发生在 0.20 秒，不能用 `time === 0.20`。某次更新可能从 0.195 走到 0.203，永远没有等于它。

```js
const crossed = before < hitAt && after >= hitAt;
if (crossed && !action.fired) {
  action.fired = true;
  spawnProjectileOrResolveMelee();
}
```

单次事件也可以用 `!fired && time >= hitAt`，当前一些角色就是这样写。多个事件点则应逐项检查跨越。若接触点为 0，要在动作进入时显式处理，不能套用 `before < 0`。

## 五、子弹拖尾为何按时间保存

若拖尾永远只保存最近 8 个位置点，低帧率下跨度大，高帧率下跨度小，尾长会随设备变化。当前小焰给每个轨迹点保存时间，保留最近一个短时间窗，再对最旧边界点插值。

细长的亮头、渐细尾巴和高速位移共同形成射击观感。拖尾是过去轨迹的可视化，不是把一条长线当成额外持续伤害区域。

同理，闪电应沿目标之间的路径画折线或使用合适的线状素材。把一张环形电特效贴在玩家身上，会变成充能光环；贴在敌人身上，也不一定就成了玩家期待的一条条链式闪电。

## 六、特效的位置需要一个明确的坐标契约

每种效果先回答它跟随谁：

| 效果 | 建议使用的定位规则 |
| --- | --- |
| 枪口闪光 | 角色武器点；若做瞬时闪光，也可记录开火时的位置 |
| 命中碎屑、齿印 | 接触点或目标局部点 |
| 地面魂灯、毒区 | 放置时保存的世界坐标 |
| 飞行子弹 | 自己的世界坐标，每步更新 |
| 大招附身光效 | 角色局部坐标，每帧随角色变换 |
| 连锁闪电 | 明确的起点、终点和分支目标 |

这是幽灯与撕咬迭代特别值得记住的经验。一个技能主体动作可以在角色身上，巨口却应在目标方向或接触区域。美术资源选对但挂载位置错，玩家仍会觉得“没有效果”。

当前幽灯魂灯选择鼠标附近活着的敌人，放到敌人脚下，随后保留在该地面位置；不是每帧追踪敌人移动。计满四次却没有合适目标时会保留待生成状态，避免对空把充能浪费掉。

## 七、打击反馈由多个短反应组成

当前项目使用了敌人短闪白、位移冲击、短暂硬直、碎屑、伤害数字、镜头震动和声音。调整时要问：反馈是否出现在接触那一刻，是否遮住下一次操作，多个敌人同时受击是否把画面和声音堆满。

“重”不等于暂停半秒。动作后摇过长会吞掉操作；全屏震动过强会让准星难对齐。命中特效可以强，持续时间却可以很短。真实帧率下降与设计的顿帧也必须分开，不要把运行卡顿解释成重量感。

## 八、Web Audio 如何工作

短音效通常先下载为 ArrayBuffer，再 `decodeAudioData` 得到 AudioBuffer。第一次真实用户操作时创建或恢复 AudioContext。每次播放创建新的 BufferSource，接到增益、声像和主输出；不要反复对同一个已经播放过的 source 调用 start。

```text
AudioBufferSource → Gain → StereoPanner → Master Gain → 输出
```

机兵还使用 DynamicsCompressor，并为事件设置声音片段的 offset、duration、音量、播放速度、最短间隔与并发上限。当前实现总声部达到 12 时会停止添加新声部，命中、射击等组还有更小的上限。

这很重要：长录音不等于每次打中都应从头完整播放。每秒很多次命中把几秒长的音尾叠起来，听起来就会糊。现在机兵使用短事件窗口、轻微淡入淡出，并在暂停时停止活动声部。

参考 [MDN：Web Audio 最佳实践](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices)。本文没有把 Howler.js 写成已使用依赖；当前主要是原生 Web Audio。

## 九、练习

固定一个木桩，只改 hitAt，观察声音与刀光是否对齐；把弹速提高 5 倍，确认线段判定仍命中；让十只怪同时受击，检查声音并发；把特效定位从角色改为接触点，感受读感变化。
