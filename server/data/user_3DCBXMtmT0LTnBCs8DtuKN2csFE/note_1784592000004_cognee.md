## 项目是什么

Cognee 是一个开源 agent memory 平台。Trending 当天新增 234 个 star。它希望把原始文本、工具轨迹、业务数据和历史会话加工成可以“remember / recall”的长期记忆，而不是每次把聊天记录粗暴塞进向量检索。

README 提供 Python API、服务端、Docker 与 MCP server，并给出 Claude Code memory 插件的集成路径：会话开始时注入相关上下文，工具调用后记录轨迹，会话结束后将临时记忆同步到长期知识图谱。示例还覆盖客服与 SQL Copilot，说明它把记忆当作任务执行状态与可复用经验的结合。

## 为什么值得看

真正困难的不是“存什么”，而是“何时写入、何时召回、何时遗忘”。只做向量相似度很容易把不相关旧信息带进当前任务，造成 context 污染；只做摘要又会失去实体关系和因果。Cognee 的路线是把数据组织、图关系和检索过程结合起来，并允许在执行后更新记忆，这比静态 RAG 更接近 agent 的实际工作流。

它对 Claude Code 的生命周期 hook 描述也很具体：把 SessionStart、UserPromptSubmit、PostToolUse、Stop、PreCompact 和 SessionEnd 分别对应到不同的记忆动作。这种拆分值得任何 agent 系统借鉴。

## 我的判断

长期记忆最容易被低估的成本是治理：过期事实、错误结论、不同用户的权限边界，以及“模型曾经猜错但后来被写进记忆”。记忆层如果没有 provenance、时间戳、可删除性和数据集隔离，规模越大越危险。因此生产化应该优先做可观察、可回滚、可过期，而不是追求“永不忘记”。

对个人工作流，它可以先用在项目决策、排错记录和反复出现的任务偏好上；对客户数据，先做隔离与审计再谈自动写入。

## 实际可用结论

- Agent memory 的单位应是可验证的事实、决策和执行结果，而不是全文聊天记录。
- 引入前先定义写入规则、失效策略、权限边界与删除路径。
