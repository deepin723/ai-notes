## 项目概览

**仓库**：TencentCloud/CubeSandbox  
**今日 Star**：665  
**来源**：腾讯云开源（Apache 2.0 许可）  
**技术栈**：Rust  
**定位**：高性能 AI 代理沙箱服务，基于 RustVMM + KVM 硬件隔离

## 核心性能数据

- **沙箱启动时间**：< 60ms（硬件隔离 VM 级别的安全，但接近容器级别的速度）
- **内存开销**：< 5MB per sandbox
- **E2B SDK 兼容**：已有 E2B 集成的代码可以直接切换到 CubeSandbox

## 技术架构

采用 RustVMM（Rust 实现的轻量级虚拟机监控器）+ KVM（Linux 内核虚拟化）实现：
- 每个沙箱是独立的硬件隔离 VM，不是容器
- VM 之间互相隔离，恶意代码无法逃逸到宿主机
- Rust 实现保证了沙箱管理层本身的内存安全

v0.5（2026年7月3日）新增：
- **AutoPause/AutoResume**：沙箱空闲自动暂停，重新激活时自动恢复（降低计算成本）
- **ARM64 支持**：可以跑在 Apple Silicon 服务器或 AWS Graviton
- **per-sandbox 网络策略**：每个沙箱独立的网络隔离规则，防止横向移动攻击
- 已加入 **CNCF Landscape**（云原生计算基金会技术图谱）

部署方式：单节点或多节点集群，支持 Terraform 一键部署。

## 为什么 AI 代理需要沙箱

AI coding agent 的核心风险之一：它能执行代码。执行代码意味着：
- 可能读取系统文件、环境变量（含密钥）
- 可能发起网络请求
- 可能安装恶意依赖
- 被提示词注入攻击后，执行非预期的操作

沙箱的作用是把代码执行限制在隔离环境里，代理做什么都只影响沙箱内部，不触及宿主机和其他服务。

现有方案的问题：
- **容器（Docker）**：隔离性不足，内核共享，有逃逸风险
- **完整 VM**：隔离性强，但启动慢（通常 > 1 秒），资源开销大
- **CubeSandbox**：微 VM，60ms 启动，接近容器的轻量，接近 VM 的隔离

## E2B 兼容的战略意义

E2B 是目前 AI 代理代码执行沙箱领域的主要商业方案，已被多个 AI agent 框架集成。CubeSandbox 声称兼容 E2B SDK，意味着：
- 使用 E2B 的项目可以无缝迁移到自托管 CubeSandbox
- 降低对云端沙箱服务的依赖（成本 + 数据主权）

这是开源项目挑战商业服务的经典路径：API 兼容 + 自托管选项。
