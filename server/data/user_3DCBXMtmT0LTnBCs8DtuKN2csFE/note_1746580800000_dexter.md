## 这个项目为什么有趣

它不是通用 AI agent，不是一个聊天机器人，**是一个垂直到"金融研究"的专用 agent**。

关键能力：
- 自动把复杂金融问题拆解成研究步骤
- 调用实时市场数据 API（损益表、资产负债表、现金流）
- 自主执行、自我验证、迭代改进
- 内置防死循环机制（步骤上限、loop detection）
- 支持 WhatsApp 集成（真的在用，不只是 demo）

运行方式像 Claude Code，但"**工具箱换成了金融数据 API**"。

---

## 作者 virattt 是谁：另一个值得关注的背景

virattt 是一个独立开发者，过去做过几个金融 AI 的开源项目，Twitter 粉丝不少。
他的打法很清晰：
1. **选定一个垂直领域**（金融）
2. **跟当前最强的通用 agent 形态对齐**（Claude Code）
3. **把数据和工具专业化**（Financial Datasets API、Exa 搜索）
4. **在社区积累声量**（开源 + 推特 + Discord）

这不是"造一个新模型"的打法，是"**把现有 agent 范式垂直化**"的打法。

---

## 为什么"垂直化 Agent"是一个大趋势

### 通用 agent 的问题

Claude Code、Cursor 这些通用 agent，什么都能做一点，但在特定领域都有明显短板：

- 金融：它不知道 DCF 怎么算、不知道可比公司分析的标准流程
- 法律：它不知道合同审查的模板、不知道判决书的结构
- 医疗：它不知道诊疗指南、不知道药物相互作用查询流程
- 学术：它不知道期刊影响因子、不知道引用链追溯

**通用 agent 的智力是"平均可用"，垂直 agent 的智力是"专业可用"**。

### Dexter 做对的几件事

1. **工具集是专业化的**（不是浏览器 + bash，而是 income statement / balance sheet / cash flow API）
2. **任务规划是领域化的**（不是"先 plan 再 act"，是"先定问题 → 找数据 → 横向对比 → 估值建模 → 撰写结论"）
3. **提示词是行业化的**（system prompt 里嵌入了金融分析师的工作范式）
4. **数据源是精选的**（Financial Datasets、Exa、FactSet——不是随便搜索）

---

## 一个值得关注的架构选择：Bun runtime

Dexter 选 **Bun** 而不是 Node.js。这是一个小但重要的信号：
- Bun 比 Node 快 2-3x（冷启动、import 速度）
- Bun 原生支持 TypeScript（不用 ts-node / tsx）
- Bun 有更好的 fetch/stream API
- Bun 生态在 AI agent 圈子里越来越流行

**为什么对 agent 工程这个选择重要**：agent 每次用户请求都要做几十次工具调用、十几次模型调用。**冷启动性能和 I/O 性能直接影响用户体验**。Bun 是目前 TypeScript agent 里最好的 runtime 选择。

这个细节透露出作者的工程审美——**不追新但选最合适的**。

## 我的判断

### ① 2026 年 AI Agent 的竞争重心是"垂直打通"，不是"通用能力"

过去 2 年大家卷模型、卷通用 agent 能力。今年开始，**垂直化的机会更大**：
- 工具专业化（领域 API 接入）
- 流程专业化（领域工作流）
- 评价标准专业化（不是"看起来对"，是"金融分析师会接受"）

Dexter 用 666 stars/天的增长证明：**一个做得好的垂直 agent，市场比通用 agent 更容易验证**（通用 agent 永远被拿去跟 Claude/GPT 比，垂直 agent 只需要跟"没有 AI 的金融研究流程"比）。

### ② "Claude Code 的垂直版"会批量出现

可预测的列表：
- **法务 Code**（合同审查、判例研究）
- **医疗 Code**（诊断辅助、文献综述）
- **审计 Code**（财务核对、内控检查）
- **产品 Code**（竞品分析、用户访谈总结）
- **学术 Code**（文献追溯、数据复现）

每一个垂直领域都会出现一个"Claude Code-like"产品。先做出来的有先发优势。

### ③ 个人开发者的机会窗口

Dexter 是一个独立开发者的作品。这说明：
**当代 AI agent 基础设施成熟度已经高到**——**一个有领域理解的独立开发者，几周时间可以做出可用的垂直 agent**。

3 年前做同样的事需要一个团队 + 6 个月。

这是独立开发者最好的时代之一。

## 对我的启示

1. **如果要做垂直 agent，选那个"你恰好有领域经验、但市面上还没有专用 agent"的细分**。金融有 Dexter 了，再做一个金融 agent 性价比低。找别人没占的领域。

2. **垂直 agent 的护城河不在代码，在数据和工具接入**。Dexter 真正值钱的是它接入了 Financial Datasets + Exa + 针对性 prompt。代码本身是 commodity。

3. **学习 Dexter 的架构模板**：
   - **一个工具模块**（领域 API 封装）
   - **一个规划模块**（领域工作流）
   - **一个验证模块**（"这个答案专业吗"）
   - **一个安全模块**（防 loop、步骤上限）

   这四个模块是任何垂直 agent 的底层结构。

4. **Bun 这个选型值得学习**。如果我要做新的 TypeScript-based agent，默认选 Bun，不选 Node——快 2-3 倍、原生 TS、生态已经足够。

## 一个延伸思考：垂直 Agent 的终局是什么

可能的结局 A：**每个专业领域 1-2 个主导产品**，像 IDE 领域最后剩 VSCode、JetBrains 两家。

可能的结局 B：**通用 agent（Claude/GPT）通过 skills 机制覆盖垂直场景**，垂直独立产品被挤压。

我的判断：**B 的压力会越来越大，但不会完全消灭 A**。

因为：
- 垂直 agent 的"数据护城河"（独家 API、独家工具链）通用 agent 短期难以复制
- 行业客户愿意为"专门给我们做的"付溢价
- 深度定制的 UI/UX 比通用 chat interface 更符合专业工作流

**未来 3-5 年的格局大概是**：通用 agent 覆盖 70% 的长尾场景，垂直 agent 在 30% 的高价值场景占主导。

Dexter 这类项目现在播下的种子，就是在争夺 5 年后"金融 agent 市场"的那个位置。
