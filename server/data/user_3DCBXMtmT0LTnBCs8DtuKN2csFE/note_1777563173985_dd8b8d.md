## 项目定位

ai-chat 是一个**多模型 AI 对话平台**，核心解决的问题是：让用户通过浏览器无需注册、输入自己的 API Key 就能访问任意 OpenAI 兼容接口，并以「逐字打出」的方式实时呈现模型回答。

---

## 技术选型总览

| 层级 | 技术 | 原因 |
|------|------|------|
| 前端框架 | Vue 3 + Composition API | 响应式 + SFC 组件化，HMR 极速开发 |
| 语言 | TypeScript | 强类型约束，Message 接口编译期检查 |
| 构建 | Vite | 原生 ESM，毫秒级热更新 |
| 后端 | Node.js + Express | 轻量，原生支持异步流式 I/O |
| 流式协议 | SSE（Server-Sent Events）| 单向服务器推送，比 WebSocket 更轻 |
| 包管理 | npm + concurrently | monorepo 单命令启动前后端 |

## 核心 1：SSE 流式通信完整实现

### 为什么用 SSE 而不是普通 HTTP

普通 HTTP 请求是「请求-等待-响应」模式，AI 接口生成完整回答可能需要数秒，用户看到的是**白屏等待**。
SSE 让服务器持续推送数据片段，用户看到**逐字打字效果**，体验提升显著。

### 后端 SSE 实现（server/index.js）

```javascript
app.post('/api/chat', async (req, res) => {
  const { messages } = req.body

  // ① 设置 SSE 响应头 —— 这3行是关键
  res.setHeader('Content-Type', 'text/event-stream')  // 声明是事件流
  res.setHeader('Cache-Control', 'no-cache')           // 禁止缓存
  res.setHeader('Connection', 'keep-alive')            // 保持长连接

  // ② 调用 OpenAI SDK，stream: true 启用流式模式
  const stream = await openai.chat.completions.create({
    model: process.env.OPENAI_MODEL || 'gpt-4.1',
    messages: [
      { role: 'system', content: '你是一个有帮助的 AI 助手。' },
      ...messages,   // 携带完整对话历史（多轮对话上下文）
    ],
    stream: true,
  })

  // ③ 逐个 chunk 读取并转发给前端
  for await (const chunk of stream) {
    const text = chunk.choices[0]?.delta?.content ?? ''
    if (text) {
      // SSE 格式：data: {json}\n\n
      res.write('data: ' + JSON.stringify({ text }) + '\n\n')
    }
  }

  // ④ 发送结束信号
  res.write('data: [DONE]\n\n')
  res.end()
})
```

**SSE 数据格式（服务器逐步推送）：**

```
data: {"text":"你"}

data: {"text":"好"}

data: {"text":"！"}

data: [DONE]
```

每个事件以 `data: ` 开头，以双换行结尾。这是 W3C SSE 协议规范。

### 前端 SSE 消费（App.vue streamChat）

```typescript
const streamChat = async (assistantId: string) => {
  const response = await fetch('/api/chat', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      messages: messages.value
        .slice(0, -1)  // 去掉末尾占位的空 assistant 消息
        .map(({ role, content }) => ({ role, content })),
    }),
  })

  const reader = response.body!.getReader()  // 获取流读取器
  const decoder = new TextDecoder()          // Uint8Array → UTF-8 字符串
  const assistantMsg = messages.value.find(m => m.id === assistantId)!

  while (true) {
    const { done, value } = await reader.read()  // 读取一块字节
    if (done) break

    const lines = decoder.decode(value).split('\n')  // 按行分割
    for (const line of lines) {
      if (!line.startsWith('data: ')) continue       // 只处理 data 行
      const data = line.slice(6).trim()
      if (data === '[DONE]') break                    // 结束信号

      const parsed = JSON.parse(data)
      if (parsed.text) {
        assistantMsg.content += parsed.text  // 逐字追加，Vue 响应式自动更新 DOM
        await scrollToBottom()               // 每追加一次就滚到底部
      }
    }
  }
}
```

**三个关键技术点：**
1. `reader.read()` 是异步迭代，每次读取「网络到来的字节块」
2. `TextDecoder` 把二进制转成 UTF-8，中文是多字节编码必须用这个
3. `assistantMsg.content += parsed.text` 利用 Vue 3 响应式，追加即重渲染

## 核心 2：多模型路由设计

### 服务器配置解耦

```javascript
// server/index.js
const openai = new OpenAI({
  apiKey:  process.env.OPENAI_API_KEY,   // 用户提供的 Key
  baseURL: process.env.OPENAI_BASE_URL,  // ← 关键：可指向任意兼容接口
})
```

**切换模型只需改 .env 文件，代码零修改：**

```env
# 用自有代理（同时支持多个模型）
OPENAI_BASE_URL=https://bobdong.cn/v1
OPENAI_MODEL=gpt-4.1

# 切换到 Claude
OPENAI_BASE_URL=https://api.anthropic.com/v1
OPENAI_MODEL=claude-opus-4-6
```

### 前端用户配置传递方式

```typescript
// 用户在 ApiKeySetup 输入的 Key 存到 localStorage
localStorage.setItem('api_key', key)

// 每次 fetch 通过 Header 携带（不在 URL 中，不会被日志记录）
headers: {
  'x-api-key':  props.apiKey,
  'x-base-url': props.baseUrl,
}
```

后端读取 Header，而不是死用环境变量中的 Key，实现**零数据库、零账号风险**设计。

## 核心 3：消息路由分发（文字 vs 图片）

```typescript
// 图片请求识别（正则关键词匹配）
const isImageRequest = (text: string): boolean => {
  return /画|生成图|生成一张|画一张|画个|帮我画|给我画|绘制|画幅|来张图/.test(text)
}

const sendMessage = async (content: string) => {
  // 1. 添加用户消息
  messages.value.push({ id: crypto.randomUUID(), role: 'user', content, createdAt: new Date() })
  // 2. 创建空的 assistant 占位消息（用于流式追加）
  const assistantId = crypto.randomUUID()
  messages.value.push({ id: assistantId, role: 'assistant', content: '', createdAt: new Date() })

  // 3. 智能路由
  if (isImageRequest(content)) {
    await generateImage(content, assistantId)  // POST /api/generate-image
  } else {
    await streamChat(assistantId)              // POST /api/chat，SSE 流式
  }
}
```

**路由决策流程：**

```
用户输入文字
  ↓
  正则测试 isImageRequest()
  ├─ 包含「画/生成图/绘制」→ generateImage() → POST /api/generate-image → base64 PNG
  └─ 普通对话          → streamChat()     → POST /api/chat      → SSE 逐字流
```

## 核心 4：Message 占位模式（用户体验关键）

```typescript
// 发送前先插入空的 assistant 消息
const assistantId = crypto.randomUUID()
messages.value.push({
  id: assistantId,
  role: 'assistant',
  content: '',        // ← 空内容，触发 MessageBubble 的「打字动画」
  createdAt: new Date(),
})

// MessageBubble.vue 中：
// content 为空 → 显示三点跳动动画
// content 有内容 → 显示文字
```

这样用户提交消息后**立刻**看到气泡出现并显示动画，而不是等到第一个字来了才出现，感知延迟更低。

## 核心 5：Vite 开发代理（解决跨域）

```typescript
// vite.config.ts
export default defineConfig({
  server: {
    port: 5173,
    proxy: {
      '/api': {
        target: 'http://localhost:3000',
        changeOrigin: true,  // 修改 Origin 头，后端不会拒绝
      },
    },
  },
})
```

**浏览器同源策略问题：**
- `localhost:5173`（前端）→ `localhost:3000`（后端），端口不同 = 跨域
- Vite 代理把 `/api/*` 请求转发到后端，对浏览器来说始终是同源，CORS 消失
- **生产环境无需代理**：前端 Vercel 直接请求 Railway 的公网域名

## 部署架构图

```
用户浏览器
    │ HTTPS
    ▼
Vercel CDN（全球边缘，静态 JS/CSS/HTML）
    │ 用户打开页面，下载 Vue SPA
    │ 用户发送消息 → POST https://railway-backend.up.railway.app/api/chat
    ▼
Railway Docker 容器（Node.js Express 常驻进程）
    │ 携带用户 x-api-key 转发请求
    ▼
OpenAI 兼容接口（https://bobdong.cn/v1）
    │ SSE 数据流返回
    ▼
Railway → 浏览器（透传 SSE 流）
    │ 逐字追加 → Vue 响应式渲染
    ▼
用户看到「逐字打出」效果
```

**为什么后端必须在 Railway（容器）而不是 Vercel（Serverless）：**
- Vercel Functions 超时上限 60s，SSE 长连接会被强制中断
- Railway 是常驻 Docker 容器，无超时限制，SSE 连接可持续数分钟

## 安全设计要点

1. **API Key 存储**：仅存在 `localStorage`，不上传服务器，后端不持久化
2. **Header 传输**：Key 在 `x-api-key` Header 中，不出现在 URL，不会被日志记录
3. **CORS 设置**：生产环境后端应限制 `Access-Control-Allow-Origin` 为前端域名
4. **无用户数据库**：无注册无账号，零数据泄露风险面
