## 项目信息

- **仓库**：DayuanJiang/next-ai-draw-io
- **今日 Star**：81
- **语言**：TypeScript（Next.js + React 19）
- **Live Demo**：next-ai-drawio.jiang.jp
- **赞助商**：ByteDance Doubao（用 glm-4.7 模型）

---

## 核心功能

这是一个把 AI 对话与 draw.io 图表编辑器集成的 Web 应用：

- **自然语言 → 架构图**：用文字描述需要什么图，AI 直接生成
- **对话式修改**：不满意可以继续对话调整，而不是手动拖拽节点
- **MCP Server**：提供 MCP 接口，可以在 Claude Code 中直接调用绘图能力

典型使用场景：
- 系统架构设计（"帮我画一个微服务架构图，包含 API Gateway、3个服务和数据库"）
- 流程图生成（"把这个业务流程转成标准流程图"）
- 技术方案可视化（把文档里的描述直接转成可编辑的图表）

---

## 部署方式

支持多种部署：
- **在线体验**：直接访问 next-ai-drawio.jiang.jp
- **Desktop App**：官方打包好的桌面应用
- **Docker**：`docker run` 一键自托管
- **Vercel / EdgeOne Pages**：前端部署

---

## 为什么值得关注

draw.io 本身已经是架构图领域的事实标准（.drawio 文件格式被 VS Code、Confluence 等广泛支持），把 AI 接入这个已有生态是一个聪明的切入点：

1. **不用重造轮子**：不是重新做一个 AI 绘图工具，而是给现有工具加 AI 层
2. **格式互通**：生成的图可以直接用 draw.io 原生编辑器打开修改
3. **MCP 接口**：意味着可以嵌入更大的 AI 工作流，比如"写完文档后自动生成架构图"

## 我的判断

81 星相对较低，但这个方向本身有独特价值。

反直觉的观察：**架构图是 AI 编程助手里最被忽视的场景**。大家都在讨论 AI 写代码，但"把系统设计转成图"是每个工程师都会遇到的高频需求，而且用 AI 做的质量已经相当不错。

当前的限制：
- AI 生成的图在复杂度很高时容易布局混乱（节点重叠、连线交叉）
- 语义理解还不够精确，需要多轮对话才能达到预期效果
- glm-4.7 是字节的模型，质量相比 Claude / GPT-4 有差距

**最实用的用法**：把它当做"草图生成器"而不是"最终稿输出器"——用对话快速生成一个 80% 正确的初稿，然后在 draw.io 里手动精调最后 20%。这个工作流的效率提升非常显著。

## 对我的启示

- draw.io 格式通用性强，AI + draw.io 是一个值得早期布局的效率工具场景
- MCP 接口的设计让 next-ai-draw-io 可以成为更大 agent 工作流的一部分
- 自部署版本可以接入 Claude API，获得比 Doubao 更高质量的图表生成
