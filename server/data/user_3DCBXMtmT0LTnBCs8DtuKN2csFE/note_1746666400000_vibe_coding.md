## 核心事实

作者是开源项目 Fantastic-admin（Vue 后台模板）的维护者。他在五一假期做了个新产品：

- **产品**：One-step Console（一步控制台），灵感来自 macOS 台前调度
- **时间**：7 天
- **成本**：30 元（主要是 AI API 调用费）
- **方法**：几乎纯 vibe coding（跟 AI 对话着写代码，自己基本不直接敲）

关键产品设计：
- 每个功能模块是一个**独立窗口**
- 多个窗口组成一个**舞台**，一个舞台默认 1 个窗口，最多 4 个
- **切换舞台 = 切换工作场景**，免去了传统 SPA 的路由跳转 + KeepAlive 烦恼
- 未激活的舞台缩小停靠在侧边栏，**LRU 淘汰**管理内存

---

## 为什么这个案例值得细看

### 1. 他用 7 天，做了传统流程里 2-3 个月的工作

对比：
- 传统流程：想法 → 原型 → UI 设计 → 前端框架搭建 → 功能开发 → 测试 → 发布。一个独立开发者 2-3 个月
- 他的流程：想法 → Gemini 生成原型验证可行 → 接下来 7 天 vibe coding 出成品

**时间压缩 8-10 倍**。这不是偶然，是生产方式的变化。

### 2. 他做的不是简单 CRUD，是有创新交互的产品

很多人对 vibe coding 的认知：
- ❌ "只能写简单的 TODO list"
- ❌ "复杂功能还得自己写"

这个案例打破了这种印象。**舞台切换 + 多窗口 + LRU 缓存 + 拖拽预览**，这套交互的工程复杂度不低——传统独立开发者做至少得是个"通 React 内部机制"的中高级工程师。

作者承认他自己是 Vue 后台领域的老手，但**具体代码他没有亲自写**。

### 3. 30 元的成本让"试错"的门槛低到离谱

过去一个想法要验证 → 至少一周人力 → 工程师成本 1 万块起步。
现在一个想法要验证 → 30 块 + 一杯咖啡的时间 → 直接看结果。

**这意味着什么？**

意味着创业的游戏规则在变：
- 过去是**"想好再做"**（因为做的成本高，错了代价大）
- 现在是**"边做边想"**（成本极低，错了再改）

这不是"Lean Startup"的继续，是它的**量子化版本**——迭代周期从周/月级压缩到天/小时级。

## 对这个产品本身的判断

### 优点

- **舞台切换的交互设计确实好**，解决了 admin 系统"开 N 个标签页很乱"的实际痛点
- **LRU 缓存**的技术选型正确（内存敏感、用户习惯）
- **视觉反馈丰富**（侧边栏停靠、拖拽预览）——这些细节对 admin 类产品不多见

### 可能的问题

- **7 天纯 vibe 出的代码，维护性未知**。AI 写代码倾向"先能跑"，不一定遵循长期架构
- **未知的 bug 存量**。作者说"还没发布"，意味着还没经过真实用户检验
- **差异化能否持续**？交互再好，如果别人也用 Gemini 7 天 vibe 一个类似的出来，护城河很浅

---

## 我的判断

### ① Vibe coding 正在把"独立开发者"重新定义

**过去的独立开发者 = 能独自覆盖全栈的工程师**。门槛高。
**现在的独立开发者 = 有产品直觉 + 会用 AI 工具的人**。前端/后端/UI 都外包给 AI。

这意味着：
- **审美、直觉、选品、推广**的权重上升
- **编程能力本身**的权重下降
- **设计师 / 产品经理 / 领域专家**可以更容易转型做产品

### ② "7 天做一个产品"不是个案，会变成趋势

作者用的是 Gemini。同样能跑这套流程的还有 Claude Code、Cursor、Continue。

**未来 12 个月**：会看到大量"7 天 vibe"级别的产品涌现。GitHub 上、Product Hunt 上、独立开发者社群里。

但真正有价值的只会是 **2-3%**。其余的是"copy paste" - 看到别人做的，自己也 vibe 一个，没有真正的差异化。

这就是**价值向两极分化**：
- **顶部 3%**：真有 insight 的独立开发者，得益于 AI 把他们的 insight 快速产品化
- **底部 97%**：一堆同质化的"我也做了个 XX"，淹没在噪音里

### ③ 工具和能力的关系在变化

过去：**工具越强，能力门槛越高**（Photoshop、Excel 高级用法）
现在：**工具越强，能力门槛越低**（AI 编程工具、AI 设计工具）

但**"用好工具"本身是一种新能力**。Vibe coding 不是"我不用懂编程"，是"我需要懂**跟 AI 协作**、**判断 AI 输出**、**指挥 AI 架构**"——这是新的核心技能。

## 对我的启示

### 立刻可以做的事

1. **把积压的 side project 清单重新审视一遍**。用 vibe coding 的成本，原来"做不完所以没做"的东西，现在 90% 都能 1-2 周做出来
2. **试一次纯 vibe coding**——整个项目自己一行代码不敲，只给 AI 发指令。体验一下新模式
3. **关注 AI Tokens 的成本趋势**。30 元 = 7 天的成本意味着"天花板"——当 AI 模型继续降价，甚至可能出现"10 元做一个产品"

### 更深的反思

我自己过去一个月用 Claude 做了很多事：给笔记应用加新能力、做 UI 改造、接 Cursor CLI……**如果没有 AI，这些我大概也能做，但不会真的去做**——成本太高、回报不明。

**AI 的真正价值不是"让事情做得更快"，是"让原本不会做的事变得值得做"**。

作者 One-step Console 这个产品就是这样——在 vibe coding 之前，他不会花 2 个月做这个"验证一下"的产品。但 7 天 / 30 块的成本，就让"试一下"变成合理选项。

**"可行性曲线向下移"** 永远是技术进步最重要的后果。

## 一个延伸问题

**如果人人都能 7 天做一个产品，最后值钱的是什么？**

短期值钱的是：**选品能力 + 执行速度**。
中期值钱的是：**用户获取 + 品牌**。
长期值钱的是：**对某个细分人群的深度理解**。

"我能做出这个产品"会越来越不值钱。"我知道这个产品该给谁做、怎么推、怎么迭代"会越来越值钱。

**编程从技能变成常识**，就像读写一样——每个人都会，但只有少数人能靠它赚到钱。
