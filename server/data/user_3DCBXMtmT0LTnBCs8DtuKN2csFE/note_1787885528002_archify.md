## 项目是什么

[Archify](https://github.com/tt-a1i/archify) 是面向 Codex、Claude Code、Cursor 等代理的制图 Skill，今天约新增 4,239 Star。它把系统描述或真实代码库转换为架构、工作流、时序、数据流和生命周期五类交互图，最终输出一个自包含 HTML，也支持 PNG、SVG、WebM 和分享卡片。

## 为什么不是普通 Mermaid 包装

核心设计是一层类型化 JSON IR。代理先写结构化候选，再由确定性渲染器和校验器处理几何、连线、遮挡与导出，而不是让模型直接拼 SVG 坐标。普通场景限制在约 12 个主节点，默认自动路由；只有诊断指出问题时才添加几何控制，减少“修一条线、坏三条线”的连锁反应。

交付命令会冻结输入快照、验证、渲染并输出 SHA-256 收据。项目还支持 Before/Delta/After 架构比较、上下游路径追踪和受控演示动画。这里的关键不是动画，而是每个交互都只能沿已声明拓扑发生，避免观看者从视觉效果中读出不存在的关系。

## 我的判断

Archify 抓住了生成式可视化的真正缺陷：模型擅长提出结构，却不擅长稳定处理几何与可重复交付。用“语义 IR + 确定性编译器 + 验证收据”分工，远比让 LLM 直接画最终图可靠。这套思路也适用于 PPT、网页和报告生成。

它的限制是输入证据仍由代理抽取。图形验证可以证明线没穿过节点、输出字节没变，却不能证明代理正确理解了代码库。所谓“可验证”应拆成几何正确、来源可追溯和语义正确三层，Archify 主要解决前两层。

## 对我的启示

生成复杂资产时不要让模型一步到最终像素。先建立小而清晰的结构化规范，再用确定性工具渲染与验收；同时把源文件版本和交付哈希记录下来，成果才真正可维护。
