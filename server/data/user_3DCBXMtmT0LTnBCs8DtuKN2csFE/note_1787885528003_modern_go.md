## 项目是什么

[go-modern-guidelines](https://github.com/JetBrains/go-modern-guidelines) 是 JetBrains 给 AI 编码代理准备的现代 Go 指南，今天约新增 300 Star。它会读取项目 `go.mod`，只推荐目标版本实际支持的语言和标准库特性，并覆盖 Go 1.0 到 1.27 及 `modernize` analyzer 的主要规则。

例如代理会优先使用 `max`、`slices.Contains`、`cmp.Or` 等现代写法，也知道 Go 1.26 的 `errors.AsType[T]`。这不是追新语法炫技，而是解决模型训练语料的两个偏差：知识截止导致它不知道新 API，频率偏差又让它即便知道，也倾向生成互联网上数量更多的旧式循环和样板代码。

## 工作方式

指南被封装为 Junie、Claude Code、Codex 和 Cursor 可发现的插件/Skill。安装后由代理在 Go 任务中自动调用；辅助 CLI 会安装到独立缓存，不直接修改项目。它首先确定 Go 版本，再把“现代化”约束在兼容边界内，避免对旧仓库生成无法编译的代码。

## 我的判断

这是一个很小但方向正确的产品：代码代理的质量不只取决于大模型能力，也取决于是否拿到当前生态的短小权威约束。把完整官方文档塞进上下文既贵又嘈杂；把高频迁移规则压缩成版本感知 Skill，性价比更高。

但“现代”不自动等于“更清晰”。一些新 API 会降低样板代码，也可能让不熟悉新版本的团队难以维护。指南应服从仓库的最低版本、团队风格和性能测试，而不是成为自动升级宗教。

## 对我的启示

给代理补知识时，最有效的不是建立巨型资料库，而是围绕真实错误模式做小型、可触发、带版本边界的 Skill。前端也可以用同样方法维护 Vue、React、TypeScript 的“本项目现代写法”。
