## 项目是什么

[Claude-Mem](https://github.com/thedotmack/claude-mem) 是跨会话代理记忆插件，今天约新增 143 Star。它自动捕获工具调用与关键观察，生成语义摘要，在后续会话中按需注入相关上下文，并提供本地 Web Viewer、搜索 Skill、引用 ID 和隐私排除标签。

## 工作原理

系统挂在 Setup、SessionStart、UserPromptSubmit、PreToolUse、PostToolUse、Stop 等生命周期节点。工具执行后的原始记录被送入 worker，形成更短的 observation；会话结束时进一步总结。新会话不是重放全部历史，而是先给高层索引，再按问题逐层展开，这就是“渐进披露”。

这种设计同时控制两种成本：上下文窗口不会被完整日志淹没，用户又能通过引用回到具体观察。安装命令会注册 hooks 和 worker；单纯全局安装 npm 包并不会完成插件配置。

## 我的判断

Claude-Mem 最值得学的不是“永久记住”，而是把记忆视为独立数据产品：采集、压缩、检索、注入、引用和遗忘都有明确阶段。真正有用的记忆应保存决定、约束、失败原因和项目状态，而不是把每句聊天都当资产。

风险在于自动捕获会积累私密路径、命令输出和过时结论。`<private>` 排除标签是补救，不是完整治理。还需要保留期、按项目隔离、可审计删除，以及“当前事实覆盖旧事实”的冲突规则。

## 对我的启示

你现在用全局 AGENTS.md 保存少量稳定偏好，是高精度的显式记忆；AI Notes 保存研习成果，是知识记忆；Claude-Mem 这类系统适合补项目过程记忆。三者应分层，不能让自动日志替代经过确认的长期规则。
