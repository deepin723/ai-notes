## 项目定位

Vki（神经元智能知识库）解决的核心问题：**普通笔记记录是线性的，而知识是网状的**。Vki 通过 LLM 自动把原始笔记编译为 6 类结构化 Wiki 页面，并用 `[[wikilink]]` 语法构建页面间的知识网络。

---

## 技术选型总览

| 层级 | 技术 | 选型原因 |
|------|------|--------|
| 存储 | Markdown 文件 + YAML frontmatter | 无数据库，可读，可版本管理 |
| Frontmatter 解析 | gray-matter | 业界标准，读写 YAML 头 + Markdown 体 |
| 路由 ID | uuid v4 | 全局唯一，无碰撞风险 |
| Markdown 渲染 | marked.js | 轻量，浏览器端解析 |
| Wikilink | 正则 + 事件委托 | 无需路由库，点击跳转 |
| LLM 接口 | /chat/completions + JSON 输出 | 一次调用生成全部类型 |
| 后端 | Node.js + Express | 文件 I/O 天然异步 |

## 核心 1：文件存储数据模型

### 每条笔记是一个 .md 文件

文件名格式：`note_{timestamp}_{random6chars}.md`

```markdown
---
id: "note_1714385000000_abc123"
type: "raw"
title: "Vue 3 响应式原理学习笔记"
tags:
  - Vue3
  - 响应式
  - 前端
links:
  - "Proxy 对象"
  - "ref 与 reactive"
sourceId: null
compilledAt: null
created: "2026-04-29T10:00:00.000Z"
updated: "2026-04-29T10:30:00.000Z"
---

Vue 3 的响应式系统基于 [[Proxy 对象]] 实现...

## 核心 API
- [[ref 与 reactive]] 是最常用的两个响应式原语
- computed 是派生响应式值
```

**Frontmatter 字段说明：**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 唯一标识符，文件名的一部分 |
| type | 枚举 | raw/entity/concept/summary/synthesis/comparison/qa |
| title | string | 笔记标题，wikilink 用标题匹配 |
| tags | string[] | 用于筛选和分类 |
| links | string[] | 本页面引用的其他页面标题 |
| sourceId | string | 编译页专属，指向原始笔记 ID |
| compiledAt | ISO string | 上次编译时间 |
| created/updated | ISO string | 时间戳 |

## 核心 2：gray-matter 读写实现

### 什么是 gray-matter

gray-matter 是一个解析「YAML frontmatter + Markdown body」格式的库。文件格式是：

```
---
key: value
---
Markdown 正文内容
```

### server/index.js 中的读写工具函数

```javascript
import matter from 'gray-matter'
import fs from 'fs'
import path from 'path'
import { v4 as uuidv4 } from 'uuid'

const DATA_DIR = path.join(path.dirname(fileURLToPath(import.meta.url)), 'data')

// 确保 data 目录存在
if (!fs.existsSync(DATA_DIR)) fs.mkdirSync(DATA_DIR, { recursive: true })

const notePath = (id) => path.join(DATA_DIR, id + '.md')

// 读取单条笔记
const readNote = (id) => {
  const fp = notePath(id)
  if (!fs.existsSync(fp)) return null
  const { data, content } = matter.read(fp)
  // data = frontmatter 对象（已转成 JS 对象）
  // content = --- 之后的 Markdown 正文（已去掉首尾空格）
  return { ...data, content: content.trim() }
}

// 写入笔记
const writeNote = (meta, content) => {
  const fp = notePath(meta.id)
  // matter.stringify 把 JS 对象转成 YAML frontmatter + Markdown body
  const str = matter.stringify(content || '', meta)
  fs.writeFileSync(fp, str, 'utf8')
}

// 列出所有笔记（只返回 meta，不含 content）
const listNotes = () => {
  if (!fs.existsSync(DATA_DIR)) return []
  return fs.readdirSync(DATA_DIR)
    .filter(f => f.endsWith('.md'))
    .map(f => {
      const { data } = matter.read(path.join(DATA_DIR, f))
      return data  // 只返回 frontmatter
    })
    .filter(Boolean)
    .sort((a, b) => new Date(b.updated) - new Date(a.updated))  // 按更新时间降序
}
```

**gray-matter 的 stringify 输出示例：**

```javascript
matter.stringify('这是正文内容', {
  id: 'note_123',
  title: '测试笔记',
  type: 'raw',
  tags: ['Vue', 'JS'],
  created: '2026-04-29T10:00:00.000Z',
})

// 输出：
// ---
// id: note_123
// title: 测试笔记
// type: raw
// tags:
//   - Vue
//   - JS
// created: '2026-04-29T10:00:00.000Z'
// ---
// 这是正文内容
```

## 核心 3：CRUD API 实现

```javascript
// GET /api/notes - 列出所有笔记（轻量，不含 content）
app.get('/api/notes', (req, res) => {
  res.json(listNotes())
})

// GET /api/notes/:id - 获取单条（含 content）
app.get('/api/notes/:id', (req, res) => {
  const note = readNote(req.params.id)
  if (!note) return res.status(404).json({ error: '笔记不存在' })
  res.json(note)
})

// POST /api/notes - 创建 raw 笔记
app.post('/api/notes', (req, res) => {
  const { title, content, tags = [] } = req.body
  const id  = 'note_' + Date.now() + '_' + uuidv4().slice(0, 6)
  const now = new Date().toISOString()
  const meta = {
    id, type: 'raw', title, tags,
    links: [], sourceId: null, compiledAt: null,
    created: now, updated: now,
  }
  writeNote(meta, content)
  res.status(201).json(meta)
})

// PUT /api/notes/:id - 更新笔记
app.put('/api/notes/:id', (req, res) => {
  const note = readNote(req.params.id)
  if (!note) return res.status(404).json({ error: '笔记不存在' })
  const { title, content, tags } = req.body
  const updated = { ...note, title, tags, updated: new Date().toISOString() }
  const { content: _oldContent, ...meta } = updated  // 把 content 从 meta 剥离
  writeNote(meta, content)
  res.json(updated)
})

// DELETE /api/notes/:id - 删除笔记
app.delete('/api/notes/:id', (req, res) => {
  const fp = notePath(req.params.id)
  if (!fs.existsSync(fp)) return res.status(404).json({ error: '不存在' })
  fs.unlinkSync(fp)  // 直接删除文件
  res.json({ ok: true })
})
```

## 核心 4：LLM 编译引擎

### 编译流程

```
原始笔记内容
    ↓
POST /api/compile/:id
    ↓
构建 System Prompt（要求返回 JSON）
    ↓
调用 ${baseUrl}/chat/completions
    ↓
LLM 输出 JSON（包含最多6种类型的内容）
    ↓
清理 JSON（去掉 ```json 代码块包裹）
    ↓
JSON.parse()
    ↓
为每个存在的类型创建一个 .md 文件
    ↓
更新原始笔记的 compiledAt 字段
    ↓
返回 { pages: [{id, type, title}, ...] }
```

### server/index.js compile 端点

```javascript
app.post('/api/compile/:id', async (req, res) => {
  const note = readNote(req.params.id)
  if (!note || note.type !== 'raw') {
    return res.status(400).json({ error: '只能编译 raw 类型笔记' })
  }

  const apiKey = req.headers['x-api-key']
  const baseUrl = req.headers['x-base-url'] || 'https://bobdong.cn/v1'

  // LLM System Prompt
  const systemPrompt = `You are a knowledge compilation engine.
Analyze the given note and generate structured wiki pages.
Return ONLY valid JSON (no code blocks, no explanation).
Include only types relevant to the note content:
{
  "entity":     { "title": "...", "content": "markdown with [[wikilinks]]", "links": ["title1"] },
  "concept":    { "title": "...", "content": "...", "links": [] },
  "summary":    { "title": "...", "content": "...", "links": [] },
  "synthesis":  { "title": "...", "content": "...", "links": [] },
  "comparison": { "title": "...", "content": "markdown table", "links": [] },
  "qa":         { "title": "...", "content": "**Q:** ... **A:** ..." format, "links": [] }
}
Rules:
- Use [[double brackets]] for internal links in content
- Write in the same language as the input note
- Only include types that are meaningful for this note content`

  // 调用 LLM
  const response = await fetch(baseUrl + '/chat/completions', {
    method: 'POST',
    headers: { 'Authorization': 'Bearer ' + apiKey, 'Content-Type': 'application/json' },
    body: JSON.stringify({
      model: 'gpt-4.1',
      messages: [
        { role: 'system', content: systemPrompt },
        { role: 'user',   content: note.title + '\n\n' + note.content }
      ],
      max_tokens: 4000,
      temperature: 0.3,  // 低温度，输出更稳定
    }),
  })

  const llmData = await response.json()
  let rawJson = llmData.choices[0].message.content.trim()

  // 清理 LLM 可能包裹的 ```json ... ``` 代码块
  rawJson = rawJson.replace(/^```json\s*/i, '').replace(/```\s*$/, '')

  const compiled = JSON.parse(rawJson)  // { entity: {...}, concept: {...}, ... }

  const pages = []
  const now = new Date().toISOString()
  const VALID_TYPES = ['entity', 'concept', 'summary', 'synthesis', 'comparison', 'qa']

  // 为每个类型创建独立 .md 文件
  for (const type of VALID_TYPES) {
    if (!compiled[type]) continue  // LLM 没有生成这个类型，跳过

    const pageData = compiled[type]
    const pageId   = 'note_' + Date.now() + '_' + uuidv4().slice(0, 6)

    // 提取 [[wikilink]] 中的标题作为 links 数组
    const links = (pageData.content || '').match(/\[\[([^\]]+)\]\]/g)
      ?.map(l => l.slice(2, -2)) || pageData.links || []

    const pageMeta = {
      id: pageId, type,
      title: pageData.title || note.title + ' - ' + type,
      tags:  note.tags || [],
      links: [...new Set(links)],  // 去重
      sourceId: note.id,           // 指向原始笔记
      compiledAt: now,
      created: now, updated: now,
    }
    writeNote(pageMeta, pageData.content || '')
    pages.push({ id: pageId, type, title: pageMeta.title })
  }

  // 更新原始笔记的 compiledAt 时间戳
  const { content: noteContent, ...noteMeta } = note
  writeNote({ ...noteMeta, compiledAt: now, updated: now }, noteContent)

  res.json({ pages })
})
```

## 核心 5：Wikilink 渲染与导航

### 渲染（NoteApp.vue renderMarkdown）

```typescript
import { marked } from 'marked'

const renderMarkdown = (content: string): string => {
  if (!content) return ''
  // ① 先把 [[标题]] 替换成 HTML span（带 data-title 属性）
  const withLinks = content.replace(
    /\[\[([^\]]+)\]\]/g,
    (_, title) => `<span class="wikilink" data-title="${title.replace(/"/g, '&quot;')}">${title}</span>`
  )
  // ② 再用 marked 把 Markdown 转成 HTML
  return marked.parse(withLinks) as string
}
```

**为什么要在 marked 之前处理 wikilink？**  
marked 解析时可能把 `[[` 和 `]]` 当作普通文字或转义。先替换成 `<span>` 可以确保 wikilink 正常渲染。

### 点击导航（事件委托）

```typescript
const handleContentClick = async (e: MouseEvent) => {
  const target = e.target as HTMLElement
  if (!target.classList.contains('wikilink')) return  // 不是 wikilink 就忽略
  const title = target.dataset.title
  if (!title) return
  // 在所有笔记中找标题匹配的（精确 or 模糊）
  const match = notes.value.find(n => n.title === title || n.title.includes(title))
  if (match) await openNote(match.id)  // 跳转到对应笔记
}

// 在模板中使用事件委托（监听整个 md-body，而不是每个 span）
// <div class="md-body" v-html="renderMarkdown(content)" @click="handleContentClick">
```

**事件委托的好处：**  
不需要给每个 wikilink span 单独绑定事件，一个监听器处理所有点击，性能更好，对动态生成的内容也有效。

### wikilink CSS 样式

```css
.md-body :deep(.wikilink) {
  color: var(--accent-lt);
  background: rgba(99, 102, 241, 0.08);
  padding: 1px 5px;
  border-radius: 4px;
  cursor: pointer;
  transition: background 0.15s;
  font-weight: 500;
}
.md-body :deep(.wikilink:hover) {
  background: rgba(99, 102, 241, 0.18);
}
```

`:deep()` 是 Vue 3 scoped CSS 的穿透选择器，允许在 scoped 组件中为 `v-html` 注入的 HTML 内的元素设置样式。

## 核心 6：三视图状态机

```typescript
type ViewMode = 'list' | 'editor' | 'viewer'
const view = ref<ViewMode>('list')

// 视图切换规则
// list  → editor : 点击「新建笔记」或「编辑」按钮
// list  → viewer : 点击笔记卡片
// editor → list  : 保存 or 取消
// viewer → list  : 点击「返回」
// viewer → viewer : 点击 wikilink（切换到另一篇笔记）
```

**为什么用 ref 状态机而不是路由？**
- 无需 URL 变化，没有「浏览器前进/后退」需求
- 整个应用是单页知识库，三个视图切换很简单
- 少一个依赖（vue-router），减小包体积

## 核心 7：6 类 Wiki 页面设计

| 类型 | 英文 | 适合内容 | 格式特征 |
|------|------|---------|--------|
| 实体 | entity | 人物/工具/产品 | 基础档案，多属性描述 |
| 概念 | concept | 理论/方法/技术 | 定义 + 解释 + 示例 |
| 摘要 | summary | 核心要点提炼 | 简洁列表 |
| 综合 | synthesis | 跨笔记的整合分析 | 关联多个观点 |
| 对比 | comparison | 方案/工具对比 | **Markdown 表格** |
| 问答 | qa | 知识自测 | **Q:** ... **A:** ... 格式 |

LLM 根据原始笔记内容**智能选择生成哪些类型**，而不是每次都生成全部 6 种（避免无意义的空页面）。
