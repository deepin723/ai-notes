## 从“总结一本书”变成“构造可查询知识结构”

book-to-skill 可以把 PDF、EPUB、DOCX、Markdown、HTML、RTF、MOBI，甚至整个文档目录转换成 Agent Skill。它不追求生成一篇长摘要，而是拆成核心心智模型、章节文件、术语表、模式库和速查表；Agent 只有在问题涉及相应章节时才加载那部分内容。

流程分成两半：确定性的 Python 提取器负责把不同文件变成干净文本和元数据；Skill 中的生成规范再让 Agent 提炼框架、决策规则、反模式与章节索引。技术书可以用 Docling 保留代码、表格和公式，普通文本优先使用更快的 pdftotext；扫描 PDF 会先检测文本层，缺失时停止并提示 OCR，而不是跑完整本后产出空结果。

## 它真正节省的是“发现路径”

普通 PDF 问答每次都要重新找目录、搜索、回退和重读。book-to-skill 把这笔结构化成本预先支付，之后查询只加载相关章节。项目声称在真实书籍测试中，比每次把整本书塞进上下文节省 24–51 倍 token；这是项目自测数据，方向合理，但仍需要结合自己的文档长度和查询模式验证。

它也支持向已有 Skill 追加新资料，适用于内部文档、架构决策、品牌规范、研究论文和技术标准。这个用途可能比“读书”更有商业价值。

## 我的判断

这个项目抓住了知识库常被忽略的问题：检索并不等于理解结构。按章节渐进加载、把模式和术语单独抽出，确实比一个巨大向量库更容易让 Agent形成稳定工作流。

但“来自原文”不等于“不会幻觉”。生成阶段仍可能误解章节、遗漏反例或把作者观点固化成规则；文档更新后，Skill 也可能变成过期知识。高质量版本应该保留章节锚点、抽样校验和版本信息。对有版权的书，生成结果应保持私人使用，不能因为变成 Skill 就忽略再分发限制。

## 对我的启示

高价值资料应该从一次性阅读变成可持续调用的认知工具：先建立目录和证据锚点，再按需加载，最后把新资料增量折叠进去。这和把付费社区做成持续深读笔记，本质上是同一种“结构化成本只付一次”的思路。
