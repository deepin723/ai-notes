项目地址：[apache/maka](https://github.com/apache/maka) · TypeScript · 2.2k stars · 今日约 51 stars

## Agent 的真相不应该只存在于聊天窗口

Apache Maka 是一个正在 Apache 孵化的本地优先 Agent 工作区。它把模型消息、工具调用、工具结果、权限决定和终止原因写进持久化事件记录；桌面端、TUI、CLI 和评测系统都通过同一个 Runtime Host 执行。UI 和下一次模型请求只是这份记录的不同投影，而不是唯一真相来源。

这个设计解决了常见痛点：为了缩短上下文，可以不把旧工具输出继续喂给模型，但证据不会被删除；程序崩溃后可以恢复执行现场；同一会话可以从某个 Turn 分支；失败会被分类，而不是只留一句“出了点问题”。

## 运行时与评测被放在同一条主干上

Maka 的后端主线是 Runtime Host → SessionManager → AgentRun → Runtime Event Log。桌面端提供流式会话、工具时间线、Artifact、搜索、分支和恢复；内置 Read、Write、Edit、Bash、Glob、Grep 等工具，越过沙箱边界必须审批。

它还把评测视为一等能力：实验会展开为任务 × 重复次数 × 被测主体的单元格，每次尝试保持不可变，最终记录分数、用量、成本、耗时、状态、失败原因与产物。这比在产品之外临时拼一个 benchmark 脚本更接近真正可运营的 Agent 平台。

## 我的判断

Maka 最值得借鉴的不是 Electron 界面，而是“执行事实”和“上下文窗口”解耦。Agent 会压缩上下文、重试和分支，如果系统没有不可变记录，就很难追责、复现或比较两次运行。

但它仍很早期：目前没有正式 Apache release，桌面版主要面向 Apple Silicon，Windows 只是未签名预览，Linux 尚未支持；数据格式和 CLI 仍可能变化。项目也明确说明凭证保存在本地明文文件中，只依赖操作系统账户权限，这对多人或高敏感环境不够。

## 对我的启示

可靠 Agent 的核心数据结构不是“messages 数组”，而是可恢复的事件日志。消息、工具结果、权限和失败原因都应成为不可变事实；模型上下文只是从事实中生成的临时视图。这样才能同时做好恢复、审计、评测和成本分析。
