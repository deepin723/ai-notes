## 为什么三个项目用同一套技术栈

统一技术栈的核心价值：
1. **复用认知**：在 ai-chat 学会的 SSE 模式，直接用在 ai-image
2. **复用代码**：三个项目的 ApiKeySetup.vue 几乎相同
3. **降低切换成本**：调试工具、构建配置、部署方式都一样
4. **质量一致**：TypeScript 强类型在三个项目里都提供同等保护

---

## 前端层：Vue 3 + TypeScript + Vite

### Vue 3 Composition API 核心模式

**为什么用 Composition API 而不是 Options API？**

```typescript
// Options API（Vue 2 风格，状态分散）
export default {
  data() {
    return { messages: [], isLoading: false }
  },
  computed: {
    filteredMessages() { ... }
  },
  methods: {
    sendMessage() { ... }
  }
}

// Composition API（Vue 3 风格，功能内聚）
const messages  = ref<Message[]>([])
const isLoading = ref(false)
const filteredMessages = computed(() => ...)
const sendMessage = async () => { ... }
// 相关逻辑放在一起，可提取为独立 composable
```

Composition API 把同一功能的状态+逻辑写在一起，而不是按「选项类型」拆散。对复杂组件（如 ImageGenerator 900 行）来说可读性更强。

### 响应式系统运行机制

```typescript
const count = ref(0)

// ref() 内部做的事：
// 1. 创建 RefImpl 对象：{ _value: 0, _rawValue: 0 }
// 2. get value() → 触发 track()，记录当前正在运行的 effect
// 3. set value(v) → 触发 trigger()，通知所有依赖的 effect 重新执行

// Vue 3 模板编译成 render effect：
// effect(() => { renderFunction() })
// 当 count.value++ → trigger → render effect 重新执行 → DOM 更新
```

**computed 的惰性特性：**

```typescript
// computed 不立即执行，只在被访问时执行
const doubled = computed(() => count.value * 2)
// 此时 doubled 还未执行

console.log(doubled.value)  // 现在才执行 count.value * 2
console.log(doubled.value)  // count 没变，直接返回缓存，不重新计算

count.value = 5             // 标记 doubled 为「脏」（需要重新计算）
console.log(doubled.value)  // 重新计算 = 10
```

### TypeScript 在项目中的实际作用

**1. 接口约束（编译期错误检测）：**

```typescript
interface Message {
  id:        string
  role:      'user' | 'assistant'  // 联合类型
  content:   string
  createdAt: Date
}

// 这会在编译时报错，不等运行：
const msg: Message = {
  id: '1',
  role: 'admin',  // ❌ Type '"admin"' is not assignable to type '"user" | "assistant"'
  content: 'hello',
  createdAt: new Date(),
}
```

**2. 非空断言操作符（减少 undefined 检查）：**

```typescript
const reader = response.body!.getReader()  // ! 告诉 TS：我确定 body 不是 null
const msg = messages.find(m => m.id === id)!  // ! 告诉 TS：我确定能找到
```

**3. 泛型保证类型安全：**

```typescript
const messages = ref<Message[]>([])  // 明确声明数组元素类型
// messages.value.push({ id: 1, ... })  ❌ id 必须是 string，不能是 number
```

### Vite 构建系统原理

```
开发时（npm run dev）：
  ├── 不打包，直接用原生 ES Modules
  ├── 浏览器按需请求 .vue/.ts 文件
  ├── Vite 服务器实时转译（无需等全量 build）
  └── HMR：修改一个文件，只有那个模块更新

生产时（npm run build）：
  ├── Rollup 打包（tree-shaking，只包含用到的代码）
  ├── .vue → 纯 JS
  ├── .ts  → ES2020 JS
  └── 输出 dist/ 目录（可直接部署到 CDN）
```

**为什么开发极快：**
- Vite 不会在启动时打包整个项目
- 浏览器发请求时按需转译，首次启动 < 1 秒
- HMR 只更新改变的模块，不刷新整页

### SFC（Single File Component）结构

```vue
<!-- 一个 .vue 文件包含三个部分 -->
<script setup lang="ts">
  // TypeScript 逻辑：响应式状态 + 函数 + 生命周期
  // setup 编译器宏：自动暴露给模板，无需 return
</script>

<template>
  <!-- HTML 模板：使用 Vue 指令（v-if, v-for, @click 等）-->
</template>

<style scoped>
  /* CSS：scoped 属性让样式只作用于本组件 */
  /* 编译时给选择器加 data-v-xxxxx 属性限定范围 */
</style>
```

**scoped CSS 原理：**
```css
/* 源码 */
.card { background: #fff; }

/* 编译后（加了哈希属性） */
.card[data-v-3a2b1c] { background: #fff; }
```

这样不同组件的 `.card` 不会互相干扰，即使类名相同。

## 后端层：Node.js + Express + ESM

### ESM 模块系统（type: "module"）

三个项目的 server/package.json 都有：

```json
{ "type": "module" }
```

这让 Node.js 以 ES Modules 方式解析文件，允许使用：

```javascript
// ESM 语法（现代，与浏览器一致）
import express from 'express'
import { readFile } from 'fs/promises'
import { fileURLToPath } from 'url'

export default app
export { readNote, writeNote }
```

而不是旧的 CommonJS：
```javascript
// CJS 语法（Node.js 传统）
const express = require('express')
module.exports = app
```

**ESM 的一个坑：`__dirname` 不再可用**

```javascript
// ESM 中没有 __dirname，需要手动实现：
import { fileURLToPath } from 'url'
import path from 'path'

const __filename = fileURLToPath(import.meta.url)  // 当前文件绝对路径
const __dirname  = path.dirname(__filename)          // 当前文件所在目录
```

### Express 中间件链

```javascript
const app = express()

// 1. CORS 中间件（处理跨域）
app.use(cors())

// 2. JSON 解析中间件
app.use(express.json({ limit: '10mb' }))  // ai-image 需要传 base64 图片

// 3. 路由处理函数
app.post('/api/generate-image', async (req, res) => {
  // req.body 已经被 express.json() 解析为 JS 对象
  const { prompt, size } = req.body
  // ...
})
```

**中间件执行顺序：**
```
HTTP 请求进来
    ↓
cors()  → 添加 CORS 响应头
    ↓
express.json()  → 解析请求体 JSON → req.body
    ↓
路由匹配  → 执行具体处理函数
    ↓
HTTP 响应发送
```

### 异步处理模式

三个项目都大量使用 async/await：

```javascript
// async/await 是 Promise 的语法糖，让异步代码读起来像同步
app.post('/api/chat', async (req, res) => {
  try {
    const stream = await openai.chat.completions.create(...)  // 等待连接建立
    for await (const chunk of stream) {                       // 异步迭代流
      res.write('data: ' + JSON.stringify(chunk) + '\n\n')
    }
    res.end()
  } catch (err) {
    // 任何 await 抛出的错误都在这里捕获
    res.status(500).json({ error: err.message })
  }
})
```

**`for await...of` 的工作原理：**
- 对于 AsyncGenerator（如 OpenAI SDK 的 stream），每次 `for await` 调用 `iterator.next()`
- 等待 Promise resolve，得到下一个 chunk
- 这是逐步处理流式数据最优雅的方式

### node --watch 开发模式

```json
{ "scripts": { "dev": "node --watch index.js" } }
```

`--watch` 是 Node.js 18+ 的内置文件监听功能，修改 index.js 或依赖文件时自动重启，类似于第三方工具 nodemon，但无需额外安装。

## 跨项目复用模式

### ApiKeySetup.vue 复用

三个项目都有基本相同的 API Key 配置页，差异只在品牌元素：

```typescript
// 共同模式：
const props = defineProps<{ initialKey: string; initialUrl: string }>()
const emit  = defineEmits<{ save: [key: string, url: string] }>()

const onSave = () => {
  if (!key.value.trim()) { error.value = '请输入 API Key'; return }
  emit('save', key.value.trim(), url.value.trim())
}
```

### App.vue Key 守卫模式

三个项目都相同：

```typescript
// App.vue
const apiKey   = ref(localStorage.getItem('xxx_api_key') || '')
const baseUrl  = ref(localStorage.getItem('xxx_base_url') || 'https://bobdong.cn/v1')
const showSetup = ref(!apiKey.value)  // 没有 Key → 显示配置页

const onSaveKey = (key: string, url: string) => {
  apiKey.value  = key
  baseUrl.value = url
  localStorage.setItem('xxx_api_key', key)
  localStorage.setItem('xxx_base_url', url)
  showSetup.value = false
}
```

```html
<!-- 模板：条件渲染守卫 -->
<ApiKeySetup v-if="showSetup"  @save="onSaveKey" />
<MainApp     v-else            :api-key="apiKey" :base-url="baseUrl" />
```

### CSS 变量设计系统

每个项目有自己的主题色，但变量名约定一致：

```css
/* ai-chat: 白色/浅蓝（明亮对话风格） */
:root { --bg: #f0f2f5; --accent: #6366F1; }

/* ai-image: 棕金色（艺廊风格） */
:root { --bg: #120E09; --accent: #C4813A; }

/* Vki: 深蓝/靛紫（知识库风格） */
:root { --bg: #0A0D14; --accent: #6366F1; }
```

组件内用 `var(--accent)` 而不是硬编码颜色，换主题只需改 `:root` 变量。

### 请求 Header 传递凭证模式

三个项目前端都用相同方式传递 API Key：

```typescript
// 每次 fetch 调用都带上
fetch('/api/xxx', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'x-api-key':  props.apiKey,
    'x-base-url': props.baseUrl,
  },
  body: JSON.stringify(data),
})
```

后端统一从 Header 读取：

```javascript
app.post('/api/xxx', async (req, res) => {
  const apiKey = req.headers['x-api-key']
  const baseUrl = req.headers['x-base-url'] || 'https://bobdong.cn/v1'
  // ...
})
```

## Monorepo 结构的 concurrently

```json
// 根 package.json
{
  "scripts": {
    "dev": "concurrently \"npm run dev:server\" \"npm run dev:client\"",
    "dev:client": "cd client && npm run dev",
    "dev:server": "cd server && npm run dev",
    "install:all": "cd server && npm install && cd ../client && npm install"
  },
  "devDependencies": { "concurrently": "^9.0.0" }
}
```

**concurrently 做的事：**
- 同时运行多个 npm 脚本
- 颜色区分各进程的输出
- 任一进程崩溃时通知用户
- 一个 Ctrl+C 停止所有进程

```bash
npm run dev:server  # 后台运行 Express，监听 :3000/3003/3004
npm run dev:client  # Vite 前端，监听 :5173/5178/5179

# 输出示例：
[0] Server running on http://localhost:3004
[1] VITE v5.0.0  ready in 280 ms
[1] → Local: http://localhost:5179/
```

## TypeScript 配置文件说明

每个 client 目录下有三个 tsconfig 文件：

```json
// tsconfig.json（顶层引用）
{ "references": [
    { "path": "./tsconfig.node.json" },  // Vite 配置文件的 TS 配置
    { "path": "./tsconfig.app.json"  }   // 应用源码的 TS 配置
]}

// tsconfig.app.json（应用代码）
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "ESNext",
    "moduleResolution": "bundler",  // Vite 特有，支持 .vue 等扩展名
    "strict": true,                 // 严格模式：不允许 any、null 不检查等
    "noEmit": true,                 // 只做类型检查，不生成 JS（Vite 负责）
    "jsx": "preserve"               // .vue SFC 保留 JSX（Vite 处理）
  },
  "include": ["src/**/*.ts", "src/**/*.vue"]
}

// tsconfig.node.json（Node 工具代码）
{
  "compilerOptions": {
    "module": "ESNext",
    "moduleResolution": "bundler",
    "composite": true               // 允许被其他 tsconfig 引用
  },
  "include": ["vite.config.ts"]
}
```

**为什么要分两个 tsconfig？**  
vite.config.ts 运行在 Node.js 环境，src/ 里的代码运行在浏览器环境，两者的 lib 和 module 设置不同，需要分开配置。
