## 项目是什么

[OpenMontage](https://github.com/calesthio/OpenMontage) 是开源的代理式视频生产系统，今天约新增 1,292 Star。它包含 12 条生产管线、100 多个工具和大量视频制作知识/Skill，目标是让 Claude Code、Codex 或 Cursor 直接把选题推进成脚本、素材、镜头、音频、剪辑与成片。

## 架构重点

最反直觉的设计是：系统没有一个常驻 Python“总导演”。编码代理本身就是控制平面。它读取 YAML pipeline manifest，逐阶段加载导演 Skill，调用 Python 工具注册表，写入 JSON checkpoint，再经过自审和可选的人类批准门。

这把工作流的稳定状态放在文件中，而不是藏在某次对话里。每一步都有工件与检查点，失败后可以从阶段边界恢复，也能替换具体生成器。项目因此更像一套“制作操作系统”，而非单一文生视频模型壳。

## 我的判断

OpenMontage 把代理应用的关键说得很清楚：复杂任务需要显式阶段、可恢复状态和审核门，而不是一个超长 Prompt。视频只是最明显的例子；PPT、研究报告、产品发布同样可以用 manifest + Skill + artifact + checkpoint 组织。

它的隐性成本也很高。700 多份知识文件会产生路由噪声，模型、图片、声音、版权与渲染工具的依赖组合很容易失控；“代理是控制平面”意味着行为随模型版本变化，必须通过检查点、固定输入和成品 QA 抵消不确定性。

## 对我的启示

你的演示文稿和长图工作流可以借鉴它：先固定大纲与视觉脚本，再逐页产出资产，每阶段保存中间件，最后集中验收。把过程显式化，往往比不断给模型追加修正提示更省时间。
